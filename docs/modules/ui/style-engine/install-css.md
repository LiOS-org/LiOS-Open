# Install CSS

`installCSS` is a static method provided by [StyleEngine](../style-engine.md) exposed via [context](../ui-extensions/context.md).

`installCSS` handles `CSS` installation in `head` and uses a `Set` to automatically handles deduplication.

>**Note:** For it to work, `<head>` tag needs to present in `DOM`.

## Installing CSS

`installCSS` works with a `.css` file, and uses `URL` class provided by the `DOM`.

For example:

```JS
ui.styleEngine.installCSS("../CSS/cards.css"); // Utilized the `URL` class to resolve path
```

>**Note:** If using relative path, it needs to be relative to the file the methods is executed in, and for an extension it must be relative to the extension file.

## Cascading and Priority

The `CSS` file installed, is installed via the `<link>` tag, and follows the priority same as any other `link:css`.

Because it uses `document.appendChild` the `CSS` file installed will be the last in `<head>` tag, and will be the last to overwrite cascading hence gaining most priority.

>**Note:** Because of this behavior, if installed via extensions the `CSS` file will be after the `style` tag generated by [StyleEngine](../style-engine.md) and because of this architectural choice methods like `style().set()` and even the `styleEngine.connect` won't be able to overwrite the `CSS` applied via the extensions. It is recommended to extension authors to provide a safe way to overwrite `CSS` via utilizing the `CSS variables`.

## Best Practices for extension

Because `installCSS` has built in deduplication, and `CSS` files are generally needs to be installed first, use the `initFunction`. see [Init Function](../ui-extensions/creating-an-extension.md#3-init-function).

Use `installFunction` or make your own similar implementation instead of carelessly using `document.appendChild`.

## Constraints and Limitations

1. It's global
   
   Unlike most of the things in the `UI` module, `installCSS` installs `CSS` globally, although deduplication is also handled at global level, devs must be careful about this nature as it always affects `cascading`.
2. It matches URL path
   
   Instead of hashing the contents, or matching file-name it matches URL path of the provided `CSS` file which can bear following result:-

   ```JS
   ui.styleEngine.installCSS("../CSS/cards.css");
   ui.styleEngine.installCSS("components/cards/cards.css");

   //Despite the file-name and contents being exactly same, both are considered different CSS files
   ```
3. Extension Limitation
   
   Extensions are installed after an `UI` instance is initiated, that means there is currently no way of installing a `CSS` file that the [StyleEngine](../style-engine.md) can overwrite.

    >**PS**: Will be fixed soon, till then provide a safe `API` using `CSS variables` to overcome this, for reference see the implementation of the [components extension](../../../../modules/JS/ui/extensions/components.js) it always has best practices to build components allowed by the `UI` module.
